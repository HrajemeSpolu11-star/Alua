# Ověřený embodied runtime Alua AI – 2026-10-07

Tento dokument zachycuje první skutečně úspěšný autonomní běh Alua AI ve fyzickém AluaWorld přes AluaBridge na Android/Termux.

Nejde jen o transportní test. Bylo ověřeno, že agent:

1. přijímá observations;
2. vytváří decisions;
3. odesílá akce;
4. World je fyzicky vykoná;
5. přijde pozdější sensory outcome;
6. vznikají beliefs;
7. vznikají skills;
8. část skills je označena jako reusable.

## Ověřené revize

Při úspěšném testu:

- AluaWorld: `e0a4c09`;
- AluaBridge: `4e60247`;
- Alua AI: `be69f41`.

## Původní blokující stav

Před opravami bylo možné spustit:

```bash
.venv/bin/python -m alua doctor
```

a dostat zdravý Bridge + aktivní session, ale:

```text
last_observation_sequence: 0
last_action_sequence: 0
```

E2E test měl současně:

```text
episodes: 0
decisions: 0
beliefs: 0
```

To znamenalo, že samotný Python runtime nebyl hlavní problém. AI prostě nedostávala žádný použitelný vjem.

Root cause byl nakonec nalezen ve skutečném body adapteru AluaWorld.

## Root cause 1 – World body adapter neposkytoval observations

V AluaWorld používal skutečný body adapter Lua colon metody se špatnou interpretací `self`. Tělo bylo viditelné a registrované, ale adapter nepracoval nad skutečnou LuaEntity.

Po opravě se `last_observation_sequence` okamžitě odlepil od 0 a začal růst stovkami frame.

Pozorované hodnoty během validačních běhů:

- 419;
- 371 před startem AI v nové session;
- lokální observation cursor Alua později 474.

Tím bylo potvrzeno, že perception pipeline funguje.

## Root cause 2 – `409 target_expired` ukončoval celý runtime

Po opravě observations Alua poprvé skutečně vytvořila cílovou akci, ale proces skončil:

```text
Alua chyba: 409 target_expired: target_ref není platný pro tohoto agenta
```

`target_ref` je záměrně krátkodobý handle. Je normální, že mezi observation a action občas vyprší.

Chyba nebyla v odmítnutí Bridge. Chyba byla v tom, že runtime tento recoverable stav považoval za fatální.

## Oprava stale target recovery

Runtime nyní při `BridgeHttpError(code="target_expired")`:

- neukončí proces;
- označí decision jako `stale_target`;
- nevytvoří pending expectation;
- nevytvoří falešný goal outcome;
- ponechá observation cursor posunutý;
- pokračuje dalším čerstvým vjemem.

Bridge navíc expirovaný `target_ref` z observation při čtení odstraňuje a World má delší interní TTL.

## Potvrzený autonomní běh

Po opravě se tělo `alua:1` začalo samo ve světě pohybovat.

World živý log ukazoval například:

```text
zahájil akci | agent=alua:1 | action=look
změnil směr pohledu | agent=alua:1 | seq=108
výsledek akce | agent=alua:1 | action=look | seq=108 | úspěch=ano
```

Byly vidět navazující úspěšné sekvence přibližně `102 ... 111`.

To potvrzuje, že Alua už není pouze klient API. Rozhodnutí skutečně mění fyzické tělo ve světě.

## Potvrzený stav kognitivní persistence

Po reálném běhu:

```json
{
  "agent_id": "alua:1",
  "last_observation_sequence": 474,
  "episodes": 482,
  "known_appearance_signatures": 13,
  "decisions": 235,
  "beliefs": 9,
  "pending_expectations": 1,
  "goals": 10,
  "skills": 12,
  "reusable_skills": 6,
  "schema_version": 3
}
```

Interpretace:

- `episodes=482`: observation frames se skutečně ukládají;
- `known_appearance_signatures=13`: agent odlišuje opakované perceptuální podpisy bez znalosti názvů nodů;
- `decisions=235`: policy aktivně rozhodovala;
- `beliefs=9`: proběhlo učení z následků;
- `goals=10`: vzniká cílová vrstva;
- `skills=12`: runtime agreguje zkušenosti do dovedností;
- `reusable_skills=6`: část dovedností prošla kritérii pro opakované použití;
- `pending_expectations=1`: při běžícím agentovi může být jedna aktuální akce čekající na pozdější outcome.

## Co tento test skutečně prokazuje

Byl potvrzen uzavřený embodied loop:

```text
World observation
    ->
PerceptionFrame
    ->
WorkingMemory
    ->
Goal selection
    ->
Policy / decision
    ->
ActionRequest
    ->
Bridge
    ->
World physical action
    ->
future sensory motor outcome
    ->
expectation resolution
    ->
belief update
    ->
skill evidence
```

To je první praktický důkaz, že architektura tří repozitářů funguje jako celek.

## Co test naopak neprokazuje

Úspěšný loop neznamená, že je agent už inteligentní v širším smyslu.

Pozorovaná behaviorální slabina:

- agent může provádět dlouhé série `look` akcí;
- policy je stále jednoduchá;
- goals jsou lokální a krátkodobé;
- planner není více-krokový;
- destruktivní manipulace zůstává vypnutá;
- needs/metabolismus nejsou hotové.

Další fáze proto není další přepojování Bridge, ale audit kvality rozhodování.

## Kanonický start Alua AI

Nejdříve musí běžet AluaBridge a AluaWorld.

Potom:

```bash
cd "$HOME/alua/Alua"
set -a
. ./.env
set +a
.venv/bin/python -m alua doctor
```

Před startem AI ověřit:

```text
last_observation_sequence > 0
```

Pak:

```bash
.venv/bin/python -m alua run
```

Pro pouze jeden cyklus:

```bash
.venv/bin/python -m alua run --once
```

## Kontrola persistence za běhu

V jiné Termux session:

```bash
cd "$HOME/alua/Alua"
set -a
. ./.env
set +a
.venv/bin/python -m alua status
```

Tento příkaz nespouští druhý runtime. Pouze čte kognitivní SQLite stav.

Sledovat:

- `last_observation_sequence`;
- `episodes`;
- `decisions`;
- `beliefs`;
- `pending_expectations`;
- `goals`;
- `skills`;
- `reusable_skills`.

## Interpretace typických stavů

### observations = 0

Nezačínat úpravou policy.

Nejprve ověřit:

- World body;
- World body adapter;
- Bridge session;
- `alua doctor`.

### observations rostou, decisions = 0

Problém je už v kognitivní vrstvě:

- schema/perception validation;
- pending expectation;
- goal generation;
- policy.

### decisions rostou, action sequence = 0

Kontrolovat submit do Bridge a případné HTTP chyby.

### `409 target_expired`

Je recoverable.

Aktuální runtime nesmí skončit. Pokud skončí, používá se stará verze Alua.

### beliefs = 0 při mnoha decisions

Kontrolovat:

- zda World vrací motorický sensory outcome;
- korelaci `source_sequence`;
- expectation lifecycle;
- timeout expectations;
- learning rules.

### reusable_skills = 0

Nemusí to být chyba. Skill potřebuje dostatečnou opakovanou ověřenou evidenci.

## Důležité hranice, které zůstávají platné

- Alua nikdy přímo nečte Luanti mapu.
- Alua nezná technické názvy nodů.
- `appearance_id` není sémantický název.
- `target_ref` není identita objektu.
- `target_ref` se nepersistuje dlouhodobě.
- Bridge ACK není fyzický outcome.
- Belief se mění až z pozdějšího sensory evidence.
- World vlastní fyziku a capabilities.
- AI nesmí sama domýšlet skryté fyzikální vlastnosti.
