# Audit Alua AI – 2026-10-06

## Rozsah

Audit byl proveden nad větví main na commitu ab0d119008973ca4d3ed25cba65259ab735bbbde po vzniku prvního samostatného Python runtime.

Kontrolováno:
- dokumentační pokrytí;
- hranice Alua / AluaBridge / AluaWorld;
- konfigurace;
- Bridge klient;
- schema validace;
- perception sanitizace;
- SQLite persistence;
- runtime lifecycle;
- bootstrap policy;
- boundary audit;
- GitHub Actions.

## Souhrn

Stav: první samostatný runtime je funkční základ, ale ještě nejde o hotovou autonomní inteligenci.

Poslední GitHub Actions běh pro auditovaný HEAD skončil úspěšně.

Nejdůležitější invarianty jsou v kódu skutečně vynucené, ne pouze popsané:
- Bridge URL musí být loopback;
- World token není součástí konfigurace Alua;
- síťový přístup je soustředěný do bridge_client.py;
- observation schema odmítá zakázané world-truth klíče;
- target_ref je při tvorbě persistentního perceptu odstraněn;
- dlouhodobá kognitivní data jsou v samostatné SQLite;
- změna Bridge session resetuje pouze krátkodobý observation cursor;
- první policy používá pouze wait a nevymýšlí fyziku těla.

## Ověřené komponenty

### Config

Config vynucuje:
- Python runtime mimo Luanti;
- Agent token minimálně 32 znaků;
- HTTP pouze na localhost / 127.0.0.1 / ::1;
- žádné credentials, query ani fragment v Bridge URL;
- omezený poll interval a request timeout.

### BridgeClient

BridgeClient:
- jako jediný runtime modul otevírá HTTP;
- používá Agent bearer token pouze pro chráněné endpointy;
- neposílá token na /health;
- omezuje velikost odpovědi;
- rozlišuje HTTP chybu, nedostupnost a protokolovou chybu.

### Schema boundary

Schema validator:
- přijímá pouze schema_version 1;
- kontroluje agent_id;
- používá allowlist top-level polí;
- rekurzivně blokuje známé world-truth klíče.

Toto je druhá obranná vrstva za AluaBridge.

### Perception

PerceptionFrame odděluje:
- persistentní část vjemu;
- krátkodobé target_ref;
- neprůhledné appearance_id.

target_ref se nepřenáší do persistentního perceptu.

### Store

SQLite používá WAL a transakce.

Aktuální tabulky:
- meta;
- runtime_state;
- episodes;
- appearance_stats;
- decisions;
- session_events.

Schema V1 zatím nemá migrační framework. Neznámá verze runtime bezpečně zastaví.

### Runtime

Jeden step:
1. načte Bridge session;
2. aplikuje session transition;
3. přečte observations po poslední sequence;
4. validuje a sanitizuje vjem;
5. zapíše epizodu;
6. zjistí základní novost appearance signature;
7. vytvoří deterministické decision_id;
8. uloží decision trace základní úrovně;
9. odešle ActionRequest;
10. uloží request_id a transportní status.

### Policy

Bootstrap policy používá pouze wait.

To je správně pro současný stav: přesné parametry move/look/manipulate nesmí být vymyšlené v AI repozitáři.

## Pozitivní nálezy

1. Nový Python runtime není závislý na historickém Lua companionovi.
2. Epistemická hranice je vynucena na více místech.
3. Transportní ACK není v dokumentaci vydáván za fyzický outcome.
4. Kognitivní persistence je oddělena od Bridge persistence.
5. Per-agent konfigurace je vhodná pro budoucí izolaci více Alua.
6. Dokumentace má po vzoru AluaWorld projektovou paměť, ADR, roadmapu, implementační deník, testovací a provozní dokument.

## Otevřená rizika

### P0 – chybí skutečný end-to-end běh

Dosud není ověřeno:
AluaWorld -> AluaBridge -> Alua -> AluaBridge -> AluaWorld

s persistentním AI tělem.

Bez tohoto testu nelze označit integraci za hotovou.

### P1 – persistence nemá migrace

Store pouze přijímá přesnou SCHEMA_VERSION 1.

Před rozšířením beliefs, expectations a planneru je nutné zavést:
- forward migrace;
- zálohu před migrací;
- migrační testy.

### P1 – session transition zatím nereconciliuje stará decisions

Při změně session se správně resetuje observation cursor, ale historické decisions zůstávají se svým původním statusem.

Dokud policy používá pouze wait, riziko je malé. Před aktivní manipulací musí session transition explicitně označit staré pending/planned world-specific akce jako neplatné nebo historické.

### P1 – chybí belief store a outcome attribution

Aktuální appearance_stats je pouze familiarita, nikoli naučený význam.

Ještě chybí:
- evidence links;
- confidence;
- contradictions;
- pending expectations;
- vazba action -> budoucí sensory outcome.

### P2 – appearance signature přes session

appearance_stats jsou dlouhodobé podle agent_id.

To je správné pouze tehdy, pokud kontrakt garantuje, že appearance_id má smysluplnou stabilitu přes restart/session. Pokud ne, bude nutné statistiku verzovat podle perceptual-signature epochy nebo kontrakt zpřesnit.

Tato vlastnost musí být potvrzena mezi AluaWorld a AluaBridge před tím, než appearance_id začne nést významnější naučené vztahy.

### P2 – legacy Lua metadata

Repo stále obsahuje ContentDB/Luanti metadata a starý Lua runtime.

Je to zatím úmyslná historie. Po prvním plném E2E milníku má následovat samostatné rozhodnutí, co archivovat a co odstranit.

## Verdikt

Architektonický směr je správný a první runtime je bezpečný základ.

Největší chyba by nyní byla přidat složitý planner nebo „chytrost“ dřív, než bude dokončen a otestován fyzický end-to-end kontrakt těla, session recovery a evidence-based learning.
